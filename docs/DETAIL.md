# 窗口记忆 / Window memory

让 DeepSeek Harness 桌面版在每次启动时恢复「上次关闭时的窗口大小」，并在 DSH 升级把补丁覆盖掉之后，用设置里的一个开关重新启用。

## 为什么需要它

窗口只能由 Electron 主进程创建，插件运行在 desktop host 子进程里，拿不到 BrowserWindow。所以真正的保存/恢复是一段注入到 `app.asar` 内 `lib/main.js` 的补丁：关闭与退出时原子写入几何，启动时读取并在 `new BrowserWindow` 之前应用。DSH 每次更新会整体替换 `app.asar`，补丁随之消失，窗口回到默认 1280×820。

这个插件负责补丁之外的一切：检测补丁是否还在、一键重新打补丁、校验、保留官方备份、支持一键还原。

## 设置里的开关

**设置 → 插件 → 窗口记忆**：

| 字段 | 作用 |
| --- | --- |
| `reapplyNow` | 「重新启用」开关。打开后立即打补丁；成功或失败都会自动关闭，并把结果写进状态。 |
| `status` | 只读状态行，例如「已启用：下次启动会恢复上次关闭时的窗口大小。（0.2.2-rc.5），存档 1959×1252」。最近一次操作的结果（打补丁、已在位、失败原因）会在这一行保留 10 分钟。 |
| `autoReapply` | 默认关。打开后，插件激活时若发现补丁失效会自动重打（仍然要重启才生效）。 |
| `revertNow` | 「还原」开关：打开后立即还原本插件保存的官方 `app.asar`，完成或失败后自动关闭。 |
| `details` | 只读：存档尺寸、保存时间、最近一次 `restore` 与可回滚备份。 |
| `appPath` | 应用包路径；留空则从运行中的可执行文件自动定位。 |

打补丁后必须 **⌘Q 重启**：主进程代码在启动时加载，运行中的进程不会换代码。

## 设置页（0.4 起）

除自动表单外，**设置 → 插件 → 窗口记忆** 还有一个独立页签：显示状态与几何细节，提供「重新启用 / 还原官方包 / 刷新」三个按钮，并展开查看该命名空间的原始值。数据走客户端既有的 `ctx.remote.settings` 通道，不额外开宿主接口。

## 工具

`window_keeper`，三个动作：

- `status`：状态、存档几何、最近一次 restore 日志、可回滚备份；
- `apply`：与开关同一条实现路径，打补丁并返回结果；
- `revert`：还原本插件保存的官方 `app.asar`（只在备份与当前版本一致且其他条目逐字节相同时才允许）。

## 安全性

- 打补丁前把官方 `app.asar` 备份为 `app.asar.window-keeper.bak`；版本不一致时旧备份会被改名保留，绝不拿来覆盖新版本。
- 写入走「同目录临时文件 → 校验 → rename」，中断最多留下一个临时文件，不会产生半个应用包。
- 校验：`node --check` 语法、注入区恰好 1 处、除 `lib/main.js` 外所有条目逐字节一致、数据区基址不变。
- 主进程代码的解析结果按归档的 size+mtime 缓存，设置页频繁刷新时不会反复扫描 857 KB 的 `lib/main.js`。
- **用 Electron 自己的 asar 读取器复验**：临时归档必须能被真实读取器打开并读出 `lib/main.js`、`package.json`、`preload-app.cjs`，否则中止安装；写入正式位置后还会再验一次，失败立即用备份自动还原。这条是硬性门槛：插件自己的解析器能读、但 Electron 读不了的包，会在启动时直接崩溃。
- 还原前再次比对备份与当前包：只允许 `lib/main.js` 不同，否则拒绝。

## 边界

- 仅桌面版（Electron）；Web 或源码运行环境报告 `未找到桌面应用包`，不做任何写入。
- 修改 `app.asar` 会破坏应用签名（本机无需签名即可运行，但不做 `codesign`）。若 DSH 未来启用 asar 完整性强制校验，打补丁的应用将无法启动——届时状态会显示为检查失败，应停止使用 `apply`。
- 卸载插件不会卸载补丁：补丁留在应用包里继续生效。需要恢复官方行为时，先点 `revert` 再卸载。
- 崩溃或强杀时最多丢失 400 ms 内未落盘的窗口调整。
